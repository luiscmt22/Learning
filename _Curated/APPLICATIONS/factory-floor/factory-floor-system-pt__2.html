What does it actually take to turn 'the worker pressed the green button' into a row in the ERP that finance trusts? It takes a PIN screen, a debounced material loader, a five-step transaction, and the patience to roll all of it back if Primavera coughs.

Executive summary

This is the formal Portuguese-language technical doc for the BioBraga Factory Floor system - a real-time MES (Manufacturing Execution System) built on Blazor Server, MudBlazor, EF Core, and integrated with the Primavera ERP. It documents the layered architecture (Presentation -> Service -> Data Access), the Factory_New.razor and MaterialConsumptionModal.razor components with their lifecycle methods, the IFactoryFloorService interface and its key operations (StartProductionAsync, PauseProductionAsync, EndProductionAsync, RegisterProductionAsync), the proportional material consumption algorithm with historical average suggestion, the multi-step transactional flow that updates order quantities, registers material consumption, and generates ENTSTOCK/SAIDASTOCK/DESP stock movement documents, plus PIN-based worker authentication and the 1.5s debounce on quantity-change material loading.

💡
MetaphorThe Factory Floor system is the invisible accountant standing next to every machine on the shop floor. The worker says 'I made 47 units and used this much glue,' the accountant whispers 'that is 8% over the plan, here is what your last 12 batches averaged,' then quietly walks the paperwork over to the ERP filing cabinet so nobody has to retype anything later.

1Why it exists

A real factory needs to know in real time which production orders are running on which machines, how much material was actually consumed (versus planned), and how much waste was generated - and every one of those facts has to flow back into the Primavera ERP so inventory and accounting stay consistent. Without this system, the floor relied on paper logs and the ERP saw stale data; with it, the worker scans a PIN, reports actual quantities, and the system writes the order update, the material consumption, the stock movements, and the ERP push in a single transaction.

2What it does

Provides a touch-friendly Blazor UI (Factory_New.razor) where workers see all active production orders filtered by their machine, then via PIN authentication can Start, Pause or End an order. Pause/End opens the MaterialConsumptionModal which loads materials proportionally to the reported quantity, shows historical-average suggestions and live variance, validates stock availability, and on submit walks a multi-step progress UI (update order, register consumption, generate stock entry, generate stock exit, push to Primavera, finalize). Includes today's production stats and machine filtering via URL parameters for bookmarkability.

3How it works

Layered: Razor components inject IFactoryFloorService, which uses IDbContextFactory<BioBragaContext> to open scoped DB contexts and IPrimaveraRepository for ERP calls. The material algorithm is perUnit = totalPlanned / orderQuantity, then proportionalQty = perUnit * quantityProduced rounded to 6 decimals, with an optional historical-average suggestion when QuantidadeMedia is non-zero. RegisterProductionAsync wraps everything in BeginTransactionAsync: it bumps QuantidadeFeita/QuantidadeFalta on the order, increments QuantidadeConsumida and NumeroProducoes on each gastoFase, generates CrmDocumento headers and lines for ENTSTOCK/SAIDASTOCK/DESP, then commits or rolls back. Material loading uses CancellationTokenSource debouncing (1.5s) so users can retype the produced quantity without hammering the DB. PIN auth hashes via Utils.Hash and rejects inactive workers.

Visão Geral do Sistema

Objetivo

O Sistema de Produção de Chão de Fábrica é um sistema de execução de manufatura (MES) em tempo real, projetado para rastrear ordens de produção, consumo de materiais e movimentos de inventário num ambiente de produção.

Funcionalidades Principais

Gestão de ordens de produção em tempo real

Rastreamento de consumo de materiais com análise de variância

Geração automática de movimentos de stock

Análise de padrões históricos de consumo

Suporte para produção multi-máquina

Integração com sistema ERP Primavera

Stack Tecnológica

Frontend: Blazor Server (.NET 8)

Framework UI: MudBlazor

Backend: ASP.NET Core

Base de Dados: Entity Framework Core

Integração Externa: Primavera ERP

Algoritmo de Cálculo de Material

Lógica GetMaterialsForProductionAsync

// Cálculo principal para consumo proporcional de material
var totalPlannedForOrder = mat.gf.Quantidade ?? 0;
var orderQuantity = order.Quantidade ?? 1;
var perUnitQuantity = totalPlannedForOrder / orderQuantity;
var proportionalQty = Math.Round(perUnitQuantity * quantityProduced, 6);
// Consideração de média histórica
decimal? suggestedQty = null;
if (mat.gf.QuantidadeMedia.HasValue && mat.gf.QuantidadeMedia.Value > 0)
{
suggestedQty = Math.Round(mat.gf.QuantidadeMedia.Value * quantityProduced, 6);
}

Gestão de Transações

Fluxo de Transação RegisterProductionAsync

using var transaction = await context.Database.BeginTransactionAsync();
try
{
// 1. Atualizar quantidades da ordem
order.QuantidadeFeita += quantityProduced;
order.QuantidadeFalta -= quantityProduced;
// 2. Atualizar rastreamento de consumo
gastoFase.QuantidadeConsumida += material.ActualQuantity;
gastoFase.NumeroProducoes++;
// 3. Gerar movimentos de stock
await GenerateStockMovementsAsync(...);
// 4. Confirmar transação
await transaction.CommitAsync();
}
catch
{
await transaction.RollbackAsync();
throw;
}

Key takeaways

  • IDbContextFactory plus an existingContext parameter lets the same service method participate in a caller-owned transaction or open its own
  • Debouncing material loads via CancellationTokenSource is what keeps the UI usable when the user is still typing the quantity
  • Proportional + historical-average suggestion gives workers a sanity-check before they confirm consumption
  • Stock movement creation must be inside the same transaction as the order update or the ERP and DB will drift
  • URL-parameter machine selection makes the floor view bookmarkable without server roundtrips for filtering
