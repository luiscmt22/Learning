IdentityLearning Project Knowledge Base

A complete onboarding knowledge base for the IdentityLearning Blazor Server app, covering architecture, setup, Identity features, email integration, security, deployment, and troubleshooting.

DOCX Intermediate 1,221 words 6 min read Source: Identity/IdentityProjectKnowledgeEditable.docx

ASP.NET Core Identity gives you 80% of what you need for authentication - until someone asks 'does it support 2FA with QR codes?' and 'can the emails include HTML tables?' and 'where do I store the SMTP password?' This project is the 20% that turns a tutorial into a shippable app.

Executive summary

A comprehensive project knowledge base for the IdentityLearning project - an ASP.NET Core 9.0 Blazor Server app built to demonstrate enterprise Identity features (2FA with QR codes, email confirmation, password reset, account lockout, custom ApplicationUser with Department/IsActive/ColaboratorId). Documents the solution structure, MudBlazor 8 UI integration, a SOAP-based AgileEmailService, user secrets setup, EF Core migrations, role management configuration, password policy, security headers, and deployment strategies (IIS, Azure CLI). Includes troubleshooting for common issues and a quick-start checklist.

💡
MetaphorThis project is like the IKEA manual for your authentication system. It doesn't just say 'put screws in holes' - it tells you which screwdriver to use, which holes are optional, where to find the allen keys (User Secrets), what to do if a shelf is wobbly (troubleshooting), and how to assemble the whole thing on different surfaces (IIS, Azure, local). By the time you're done, you don't just have a functioning wardrobe, you understand why each piece is there.

1Why it exists

The developer needed a production-grade reference Identity implementation they could both learn from and use as a scaffold for real apps. Most online Identity tutorials stop at 'user can register' - this project goes further into real-world requirements: 2FA enrollment with QR codes, email confirmation flow, password reset, account lockout after failed attempts, custom user properties, and a SOAP email service integration specific to the Agile ecosystem. It doubles as a knowledge base so any new developer on the team can clone, run, and extend without having to figure out the conventions from scratch.

2What it does

Provides a complete Blazor Server Identity application with registration, login, logout, email confirmation, password reset, two-factor authentication (TOTP with QR code generator), account lockout, and a profile management area. The custom ApplicationUser extends IdentityUser with Department, IsActive, and ColaboratorId for integration with the Agile employee domain. Emails are sent via a SOAP-based AgileEmailService that supports templated HTML emails and table markup ([TABLE:name]...[/TABLE] blocks). Configuration is externalized into appsettings plus User Secrets for sensitive values, and the database is managed via EF Core migrations.

3How it works

The Program.cs wires up Identity with AddIdentityCore<ApplicationUser>().AddRoles<IdentityRole>().AddEntityFrameworkStores<ApplicationDbContext>(), configures password policy (min 8 chars, digit/upper/lower/non-alphanumeric required), and account lockout (5 attempts, 5 minute cooldown). The Components/Account folder holds Razor pages for all Identity flows - Pages/ for Login/Register/Manage, Shared/ for common components, .cs files for services and helpers. MudStaticTextField is used throughout for SSR compatibility. AgileEmailService implements an SOAP client that posts to https://axrm.agileincloud.com/agMailService/agEmailService.asmx using a service key stored in User Secrets, and emails can include a custom [TABLE:name] markup that is converted to HTML tables server-side. Migrations are added with dotnet ef migrations add and applied with dotnet ef database update, and the deployment story covers IIS (no-managed-code app pool), Azure (az webapp up), and environment variables for secrets in production.

IdentityLearning Project Knowledge Base & Instructions

📋 Project Overview

Project Name

IdentityLearning - Enterprise Authentication & User Management System

Purpose

A comprehensive ASP.NET Core Blazor application demonstrating enterprise-grade authentication, authorization, and user management capabilities using ASP.NET Core Identity, designed as both a learning platform and production-ready showcase.

Technology Stack

Framework: .NET 9.0, Blazor Server-Side Rendering (SSR)

Authentication: ASP.NET Core Identity

UI Framework: MudBlazor 8.x

Database: SQL Server with Entity Framework Core

Email Service: Custom SOAP integration (AgileEmailService)

Additional: Extensions.MudBlazor.StaticInput, QR Code Generator

🔧 Development Setup

Prerequisites

.NET 9 SDK or later

SQL Server (Express or Developer edition)

Visual Studio 2022 (v17.14+) or VS Code

Git for version control

Initial Setup Steps

1. Clone and Configure

# Clone the repository
git clone [repository-url]
cd IdentityLearning
# Restore packages
dotnet restore

2. Database Configuration

Update appsettings.json with your SQL Server connection:

{
"ConnectionStrings": {
"DefaultConnection": "Server=YOUR_SERVER;Database=IdentityLearning;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true"
}
}

3. User Secrets Setup

Configure sensitive data using User Secrets:

# Initialize user secrets
dotnet user-secrets init
# Set email service credentials
dotnet user-secrets set "EmailSettings:ServiceKey" "your-service-key"
dotnet user-secrets set "EmailSettings:Password" "your-email-password"

4. Database Migration

# Apply existing migrations
dotnet ef database update
# Create new migration (if needed)
dotnet ef migrations add YourMigrationName

5. Run the Application

# Development mode
dotnet run --launch-profile https
# Or use Visual Studio F5 debugging

Email Service Integration

1. Email Configuration

The email service uses a SOAP endpoint. Configuration in appsettings.json:

{
"EmailSettings": {
"ServiceUrl": "https://axrm.agileincloud.com/agMailService/agEmailService.asmx",
"ServiceKey": "",  // Use User Secrets
"SmtpServer": "smtp-pt.securemail.pro",
"SmtpPort": 465,
"UseSsl": true,
"Username": "noreply@agileincloud.com",
"Password": "",     // Use User Secrets
"FromEmail": "noreply@agileincloud.com",
"FromName": "Your Company Name"
}
}

🔒 Security Best Practices

1. Password Requirements

Configure in Program.cs:

builder.Services.AddIdentityCore<ApplicationUser>(options =>
{
options.Password.RequiredLength = 8;
options.Password.RequireDigit = true;
options.Password.RequireUppercase = true;
options.Password.RequireLowercase = true;
options.Password.RequireNonAlphanumeric = true;
});

2. Account Lockout

options.Lockout.DefaultLockoutTimeSpan = TimeSpan.FromMinutes(5);
options.Lockout.MaxFailedAccessAttempts = 5;
options.Lockout.AllowedForNewUsers = true;

3. Two-Factor Authentication

Already implemented with QR code generation. Users can enable via: /Account/Manage/TwoFactorAuthentication

4. Security Headers

Add to Program.cs:

app.UseHsts();
app.UseHttpsRedirection();

Key takeaways

  • Extend IdentityUser by creating ApplicationUser with your custom properties and registering it in AddIdentityCore<ApplicationUser>
  • Use MudStaticTextField for SSR-compatible forms in Blazor Server Identity pages
  • Store all sensitive config (SMTP passwords, service keys) in User Secrets during dev and environment variables in prod
  • Password policy and lockout are configured inside AddIdentityCore options
  • .AddRoles<IdentityRole>() must be chained after AddIdentityCore to enable role management
  • SOAP email integration needs its own service abstraction rather than stuffing logic into controllers
  • Deploy IIS sites with 'No Managed Code' app pools for .NET Core apps
