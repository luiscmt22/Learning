Stock Service System — Formal Technical Documentation

Formal technical reference for a high-performance inventory tracking system built around a decorator-pattern cached service layer, SQL Server functions, pre-loading tasks, and graduated cache expiration.

Every time a user clicks the Stock tab on an article page, the database has to sum every inbound and outbound movement since the beginning of time to tell them how many units are on the shelf. That's expensive. Now imagine 40 users clicking that tab every minute across 50,000 articles. This is how you make that scream instead of crawl.

Executive summary

This is the formal architecture document for the Stock Service — a three-layer system (UI/Service/Data) where a CachedStockService decorator wraps a StockService implementation that talks to SQL Server table-valued functions (fn_ArtigoStockByDate, fn_ArtigoUsedInFluxo) through a raw ADO.NET connection for performance. The caching strategy uses graduated expiration: 1 hour for historical data older than 7 days, 5 minutes for recent data, nothing at all for filtered queries. Razor components pre-load expensive operations as Tasks in OnInitializedAsync so that by the time the user clicks the Stock tab, the data is already there. The doc also covers extension methods, health checks, structured logging with cache-hit tagging, cache inspection endpoints, and future enhancements like Redis and SignalR-driven invalidation.

💡
MetaphorThe Stock Service is a coffee shop with a secret second menu — the barista keeps sticky notes of the most recent orders so that if you ask for the same drink someone just ordered, they hand it to you instantly. Regular espresso from yesterday? Sticky note lasts an hour because yesterday can't change. Today's cappuccino? Sticky note lasts five minutes because someone might modify it. A custom half-caf oat milk with exactly 1.5 pumps of vanilla? No sticky note — too specific, nobody else is ordering that.

1Why it exists

Inventory queries are the most asked question in a warehouse ERP, and they're brutally expensive because computing 'what did I have on January 15th?' means summing every movement from the beginning of time up to that date. Hitting the database for every query brings the system to its knees and users wait 2-3 seconds every single time. The Stock Service exists to eliminate that wait by caching aggressively for data that doesn't change (historical stock) and conservatively for data that might (today's stock), while never caching filtered queries that are too specific to repeat. The result is sub-millisecond responses for 99% of queries with the database staying cool.

2What it does

Exposes an IStockService with four operations: GetArticleStockByDateAsync (point-in-time query), GetStockMovementsAsync (movement history with optional date filters), GetStockTotalsAsync (aggregate entradas/saídas), and CheckFluxoAsync (per-document-line flow). A CachedStockService wraps the real StockService as a decorator and checks IMemoryCache first, falling back to the real service on miss and then storing the result with an expiration chosen based on how old the queried date is. The UI layer (ArtigoDetalhe.razor) kicks off stock queries as Tasks in OnInitializedAsync so that clicking the Stock tab awaits an already-completed task.

3How it works

Under the hood, the StockService opens a raw SqlCommand on the DbContext's connection and invokes the dbo.fn_ArtigoStockByDate table-valued function with parameterized arguments — deliberately bypassing EF Core's change tracker and LINQ translation for maximum speed. A 'smart trick' adds one day to the filter date so the query includes everything up to end-of-day. Movement queries use EF Core LINQ with three joins (CrmDocumentoDetalhes → CrmDocumentos → CrmTipoDocumentos → CrmSerieDocumentos) filtered by Movstocks=true. The CachedStockService generates keys like 'stock_{artigoId}_{yyyyMMdd}' and picks an expiration: TimeSpan.FromHours(1) if the date is more than 7 days old, TimeSpan.FromMinutes(5) otherwise. The Razor layer orchestrates task reuse — if a filter hasn't changed, it awaits the existing _stockMovementsTask field; if the filter did change, it creates a new task and parallel-awaits a totals task alongside it. Health checks run a test query + cache statistics, and structured logging emits one-line entries with ArticleId, Date, CacheHit, and ExecutionTime tags for monitoring.

System Overview

Purpose

The Stock Service System provides high-performance, real-time inventory tracking with intelligent caching mechanisms to minimize database load while maintaining data accuracy.

Key Features

Real-time stock level queries with point-in-time accuracy

Historical stock movement tracking

Multi-tier caching with intelligent expiration

Async task pre-loading for perceived instant response

SQL Server function integration for complex calculations

Memory-efficient caching with graduated expiration

Architecture Philosophy

The system implements a Decorator Pattern with separation of concerns:

Core Service Layer: Business logic and database operations

Caching Layer: Memory management and cache invalidation

UI Layer: Presentation and user interaction

StockService Implementation

GetArticleStockByDateAsync

public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId, DateTime date)
{
// Critical: Add one day for end-of-day inclusion
var dateWithTime = date.Date.AddDays(1);
await using var dbContext = await _contextFactory.CreateDbContextAsync();
await using var connection = dbContext.Database.GetDbConnection();
await connection.OpenAsync();
// Direct SQL function call for performance
await using var command = connection.CreateCommand();
command.CommandText = "SELECT * FROM dbo.fn_ArtigoStockByDate(@ArtigoId, @Date)";
command.CommandType = CommandType.Text;
// Strongly-typed parameters prevent SQL injection
command.Parameters.Add(new SqlParameter("@ArtigoId", SqlDbType.Int) { Value = artigoId });
command.Parameters.Add(new SqlParameter("@Date", SqlDbType.DateTime) { Value = dateWithTime });
await using var reader = await command.ExecuteReaderAsync();
if (await reader.ReadAsync())
{
return new ArtigoStock
{
ArtigoId = reader.GetInt32(reader.GetOrdinal("ARTIGO_ID")),
Entrada = reader.GetDecimal(reader.GetOrdinal("ENTRADA")),
Saida = reader.GetDecimal(reader.GetOrdinal("SAIDA")),
Stock = reader.GetDecimal(reader.GetOrdinal("STOCK"))
};
}
return null;
}

GetStockMovementsAsync

public async Task<List<StockMov>> GetStockMovementsAsync(
int artigoId,
DateTime? startDate = null,
DateTime? endDate = null)
{
using var dbContext = await _contextFactory.CreateDbContextAsync();
// Complex LINQ join for movement tracking
var query = dbContext.CrmDocumentoDetalhes
.Join(dbContext.CrmDocumentos,
detalhe => detalhe.Documentoid,
doc => doc.Id,
(detalhe, doc) => new { detalhe, doc })
.Join(dbContext.CrmTipoDocumentos,
x => x.doc.Tipodocumentoid,
tipo => tipo.Id,
(x, tipo) => new { x.detalhe, x.doc, tipo })
.Join(dbContext.CrmSerieDocumentos,
x => x.doc.Serieid,
serie => serie.Id,
(x, serie) => new { x.detalhe, x.doc, x.tipo, serie })
.Where(x => x.detalhe.ArtigoId == artigoId && x.tipo.Movstocks == true);
// Dynamic date filtering
if (startDate.HasValue)
query = query.Where(x => x.doc.Data >= startDate.Value.Date);
if (endDate.HasValue)
query = query.Where(x => x.doc.Data <= endDate.Value.Date.AddDays(1).AddSeconds(-1));
return await query
.Select(x => new StockMov
{
ArtigoId = x.detalhe.ArtigoId,
doc = x.doc,
docdetalhe = x.detalhe,
doctipo = x.tipo,
docserie = x.serie
})
.OrderByDescending(s => s.doc.Data)
.ToListAsync();
}

Caching Strategy

Multi-Tier Cache Architecture

Cache Key Generation

// Pattern: {type}_{identifier}_{date}
var cacheKey = $"stock_{artigoId}_{date:yyyyMMdd}";

Graduated Expiration Strategy

public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId, DateTime date)
{
var cacheKey = $"stock_{artigoId}_{date:yyyyMMdd}";
// L1 Cache: Memory Check
if (_cache.TryGetValue<ArtigoStock>(cacheKey, out var cachedStock))
{
_logger.LogDebug("Stock cache hit for article {ArtigoId} at date {Date}",
artigoId, date);
return cachedStock;
}
// L2: Database Query
var stock = await _innerService.GetArticleStockByDateAsync(artigoId, date);
if (stock != null)
{
// Intelligent expiration based on data age
var cacheExpiration = date.Date < DateTime.Today.AddDays(-7)
? TimeSpan.FromHours(1)      // Historical: 1 hour
: TimeSpan.FromMinutes(5);   // Recent: 5 minutes
_cache.Set(cacheKey, stock, cacheExpiration);
}
return stock;
}

Cache Decision Matrix

Historical Stock (>7 days) 1 hour Data is immutable
Recent Stock (<7 days) 5 minutes May still change

Database Integration

SQL Server Functions

fn_ArtigoStockByDate

-- Function signature (implied)
CREATE FUNCTION dbo.fn_ArtigoStockByDate
(
@ArtigoId INT,
@Date DATETIME
)
RETURNS TABLE
AS
RETURN
(
SELECT
@ArtigoId as ARTIGO_ID,
ISNULL(SUM(CASE WHEN t.Entradasaida = 'E' THEN d.Quantidade END), 0) as ENTRADA,
ISNULL(SUM(CASE WHEN t.Entradasaida = 'S' THEN d.Quantidade END), 0) as SAIDA,
ISNULL(SUM(CASE WHEN t.Entradasaida = 'E' THEN d.Quantidade
WHEN t.Entradasaida = 'S' THEN -d.Quantidade END), 0) as STOCK
FROM CrmDocumentoDetalhes d
JOIN CrmDocumentos doc ON d.Documentoid = doc.Id
JOIN CrmTipoDocumentos t ON doc.Tipodocumentoid = t.Id
WHERE d.ArtigoId = @ArtigoId
AND doc.Data < @Date
AND t.Movstocks = 1
)

Tab Activation

private async Task OnStockTabClick()
{
if (stockTabFirstLoad && artigo != null)
{
isLoadingStock = true;
StateHasChanged();
try
{
// If pre-loaded, this completes immediately
if (_stockSummaryTask != null)
{
currentStock = await _stockSummaryTask;
}
else
{
// Fallback if not pre-loaded
currentStock = await StockService.GetCurrentStockAsync(artigo.Id);
}
// Update statistics
if (currentStock != null)
{
stat_stock_e = currentStock.Entrada;
stat_stock_s = currentStock.Saida;
}
}
finally
{
isLoadingStock = false;
stockTabFirstLoad = false;
StateHasChanged();
}
}
}

Date Filtering with Task Management

private async Task ShowStockHistory()
{
showStockHistory = true;
// Smart task reuse pattern
if (stocklist == null || !stocklist.Any() || isFiltered)
{
isLoadingHistory = true;
StateHasChanged();
try
{
if (isFiltered)
{
// Create new filtered task
_stockMovementsTask = StockService.GetStockMovementsAsync(
artigo.Id, filterStartDate, filterEndDate);
// Parallel totals calculation
var totalsTask = StockService.GetStockTotalsAsync(
artigo.Id, filterStartDate, filterEndDate);
// Await both
stocklist = await _stockMovementsTask;
var (entradas, saidas) = await totalsTask;
stat_stock_e = entradas;
stat_stock_s = saidas;
}
else
{
// Reuse or create unfiltered task
if (_stockMovementsTask == null)
{
_stockMovementsTask = StockService.GetStockMovementsAsync(artigo.Id);
}
stocklist = await _stockMovementsTask;
}
}
finally
{
isLoadingHistory = false;
StateHasChanged();
}
}
}

Best Practices

Do's ✅

Always use IDbContextFactory for database operations

Implement graduated cache expiration based on data stability

Pre-load expensive operations when possible

Use structured logging for debugging

Monitor cache hit rates

Don'ts ❌

Don't cache filtered queries (too specific)

Don't cache mutable data for long periods

Don't forget to handle cache misses gracefully

Don't use synchronous database operations

Don't ignore memory pressure warnings

Key takeaways

  • Wrap expensive services with a cached decorator so caching logic lives in one place and tests can swap it out
  • Cache expiration should be proportional to how likely the data is to change — historical = long, recent = short, filtered = don't bother
  • SQL Server table-valued functions called via raw ADO.NET skip EF Core overhead and are perfect for pure-aggregate queries
  • Start expensive Tasks in OnInitializedAsync and store them as fields — clicking a tab then awaits an already-complete task
  • Cache keys should encode everything that distinguishes the query (artigoId + date) and the format should be predictable for manual invalidation
  • Monitor cache hit rates via IMemoryCache.GetCurrentStatistics in a health check — if the ratio degrades, something upstream changed
