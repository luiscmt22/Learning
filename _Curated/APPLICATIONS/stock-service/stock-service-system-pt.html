Executive summary

This is the formal technical documentation for a production stock-tracking service built on EF Core with raw-SQL access to fn_ArtigoStockByDate and fn_ArtigoUsedInFluxo. The architecture uses the Decorator pattern to wrap StockService with CachedStockService (IMemoryCache), implements graduated cache expiration (1 hour for historical data older than 7 days, 5 minutes for recent data), uses the 'task preloading' pattern in ArtigoDetalhe.razor to start expensive operations before the user clicks the stock tab, and achieves ~99.95% improvement on cached queries (2000ms to 1ms). Includes health checks, structured logging, performance metrics, and a cache-stats debug endpoint.

💡
MetaphorThe Stock Service is a barista with a chalkboard. Every time someone asks 'how much is a latte today?' they could look it up from the till — or glance at the chalkboard where they wrote it five minutes ago. Historical prices (last month's latte) stay on the chalkboard for an hour because they never change. Today's price erases after five minutes in case the boss raised it. And while you're ordering, the barista is already making your drink before you've finished talking — that's the preloaded Task.

1Why it exists

The BioBraga application needs to show article stock levels on a high-traffic detail page (ArtigoDetalhe.razor), including historical point-in-time queries. Hitting the database for every tab click and every date filter would crush the SQL Server — the document records a naive 2000ms response time on uncached queries. The business also needs accurate, temporal stock (what was the balance on 2024-01-15?) which requires a custom SQL function walking document movements with entradas/saidas aggregation. The cache layer exists to make the user perceive instant response while preserving that accuracy.

2What it does

Exposes IStockService with four methods: GetArticleStockByDateAsync (temporal balance), GetStockMovementsAsync (filtered history with joins across CrmDocumentoDetalhes/CrmDocumentos/CrmTipoDocumentos/CrmSerieDocumentos), GetStockTotalsAsync (aggregated entradas/saidas), and CheckFluxoAsync (per-document-line flux). Wraps it in CachedStockService (decorator) registered via a Program.cs factory that composes both layers. On the UI, ArtigoDetalhe.razor kicks off a Task<ArtigoStock> at OnInitializedAsync without awaiting it, then awaits it when the user finally clicks the Stock tab — often returning instantly because it's already complete.

3How it works

Inside StockService.GetArticleStockByDateAsync, a new DbContext is created via the factory, a raw DbConnection is opened, and SqlParameters are used to call dbo.fn_ArtigoStockByDate(@ArtigoId, @Date). The date is incremented by one day to make 'end of day' inclusive. CachedStockService first checks IMemoryCache with key stock_{artigoId}_{yyyyMMdd}; on miss it calls the inner service, then caches with expiration = 1h if date is older than 7 days (immutable history) or 5m otherwise. Complex movement queries use LINQ joins across four CRM tables with AsNoTracking and date filtering via .Where(...AddDays(1).AddSeconds(-1)) for end-of-day semantics. The UI layer holds _stockSummaryTask and _stockMovementsTask fields to implement the reuse-or-refetch pattern when filters change. Health checks verify both DB connectivity and cache hit rates (hits/misses ratio). IMemoryCache is configured with SizeLimit=1000 and 25% compaction to prevent runaway memory use.

public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId,

{



       // Crítico: Adicionar um dia para inclusão de fim de dia

       var dateWithTime = date.Date.AddDays(1);

       command.Parameters.Add(new SqlParameter("@Date", SqlDbType.DateTime) {

Value = dateWithTime });



       await using var reader = await command.ExecuteReaderAsync();



       if (await reader.ReadAsync())

GetStockMovementsAsync



public async Task<List<StockMov>> GetStockMovementsAsync(

       int artigoId,

       DateTime? startDate = null,

       DateTime? endDate = null)



{

       using var dbContext = await _contextFactory.CreateDbContextAsync();



       // Join LINQ complexo para rastreamento de movimentos

       var query = dbContext.CrmDocumentoDetalhes



              .Join(dbContext.CrmDocumentos,

                     detalhe => detalhe.Documentoid,

                     doc => doc.Id,

                     (detalhe, doc) => new { detalhe, doc })



              .Join(dbContext.CrmTipoDocumentos,

                     x => x.doc.Tipodocumentoid,

                     tipo => tipo.Id,

                     (x, tipo) => new { x.detalhe, x.doc, tipo })



              .Join(dbContext.CrmSerieDocumentos,

                     x => x.doc.Serieid,

                     serie => serie.Id,

                     (x, serie) => new { x.detalhe, x.doc, x.tipo, serie })



              .Where(x => x.detalhe.ArtigoId == artigoId && x.tipo.Movstocks ==

true);



       // Filtragem dinâmica por data

       if (startDate.HasValue)



              query = query.Where(x => x.doc.Data >= startDate.Value.Date);



       if (endDate.HasValue)

              query = query.Where(x => x.doc.Data <=



endDate.Value.Date.AddDays(1).AddSeconds(-1));



       return await query

              .Select(x => new StockMov

              {

                     ArtigoId = x.detalhe.ArtigoId,

                     doc = x.doc,

                     docdetalhe = x.detalhe,

                     doctipo = x.tipo,

                     docserie = x.serie

              })

              .OrderByDescending(s => s.doc.Data)

              .ToListAsync();



}

public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId,

DateTime date)

{



       var cacheKey = $"stock_{artigoId}_{date:yyyyMMdd}";



       // Cache L1: Verificação de Memória

       if (_cache.TryGetValue<ArtigoStock>(cacheKey, out var cachedStock))

       {



              _logger.LogDebug("Stock cache hit para artigo {ArtigoId} na data

{Date}",



                     artigoId, date);

              return cachedStock;

       }



       // L2: Consulta Base de Dados

       var stock = await _innerService.GetArticleStockByDateAsync(artigoId,

date);



if (stock != null)



{



   // Expiração inteligente baseada na idade dos dados



   var cacheExpiration = date.Date < DateTime.Today.AddDays(-7)



   ? TimeSpan.FromHours(1)         // Histórico: 1 hora



   : TimeSpan.FromMinutes(5); // Recente: 5 minutos



       _cache.Set(cacheKey, stock, cacheExpiration);

}



       return stock;

}

CREATE FUNCTION dbo.fn_ArtigoStockByDate

(



       @ArtigoId INT,

       @Date DATETIME

)

RETURNS TABLE

AS

RETURN

(

       SELECT



              @ArtigoId as ARTIGO_ID,

              ISNULL(SUM(CASE WHEN t.Entradasaida = 'E' THEN d.Quantidade END),

0) as ENTRADA,

              ISNULL(SUM(CASE WHEN t.Entradasaida = 'S' THEN d.Quantidade END),

0) as SAIDA,

              ISNULL(SUM(CASE WHEN t.Entradasaida = 'E' THEN d.Quantidade



                                         WHEN t.Entradasaida = 'S' THEN -d.Quantidade END),

0) as STOCK



       FROM CrmDocumentoDetalhes d

       JOIN CrmDocumentos doc ON d.Documentoid = doc.Id

       JOIN CrmTipoDocumentos t ON doc.Tipodocumentoid = t.Id

       WHERE d.ArtigoId = @ArtigoId



          AND doc.Data < @Date

          AND t.Movstocks = 1

)

Key takeaways

  • Decorator pattern lets you bolt caching onto a service without the service knowing it's being cached
  • Graduated cache expiration (long for immutable historical data, short for mutable recent data) gets the best of both worlds
  • Task preloading — assign StockService.GetCurrentStockAsync(id) to a field in OnInitializedAsync without awaiting it, then await it when the user actually needs it — makes tab clicks feel instant
  • Raw SQL function calls via DbConnection + SqlParameter sidestep EF Core for queries that are too complex or performance-critical for LINQ
  • IDbContextFactory + await using is the safe way to do concurrent DB work in Blazor Server without crashing the scoped DbContext
  • MemoryCache needs SizeLimit and CompactionPercentage set or it will eat all your RAM
  • Health checks that report cache hit/miss ratios give you a real-time quality signal beyond just 'is the service up?'
