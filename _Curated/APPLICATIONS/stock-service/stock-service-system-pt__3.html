What if your inventory page could show today's stock levels in 0.001 seconds instead of 2 seconds, without writing a single line of new SQL? The trick isn't speed - it's memory. This is the story of how a decorator and an IMemoryCache turned a slow service into one that pretends to be psychic.

Executive summary

This is the Portuguese 'Para Totós' (For Dummies) guide to the Stock Service. It explains the two-layer architecture (CachedStockService decorating StockService), the brilliant time-based cache strategy (1 hour for historical data >7 days old, 5 minutes for recent data, no caching for filtered queries), and the four core methods: GetArticleStockByDateAsync (time machine), GetStockMovementsAsync (history book), GetStockTotalsAsync (summary), and CheckFluxoAsync (special inspector). It also covers the UI pre-loading trick in ArtigoDetalhe.razor where _stockSummaryTask starts loading in OnInitializedAsync before the user even clicks the Stock tab.

💡
MetaphorThis stock service is like having post-it notes on your desk for the questions people ask you most. The first time someone asks 'what's João's phone number?' you flip through the phone book and write the answer on a post-it. Next time? You just read the post-it. And because phone numbers from last year never change but today's might still get updated, you keep old post-its for an hour and new ones for only five minutes.

1Why it exists

Inventory checks were slow because every stock query meant counting movements from the database, and the same questions were being asked repeatedly by different users. The team needed sub-second responses without forcing the database to do the same SUM(entradas - saidas) calculation 50 times per minute.

2What it does

Wraps the real StockService in a CachedStockService that uses IMemoryCache with a smart time-based expiration policy. Historical data (more than 7 days old) is cached for 1 hour because old stock numbers don't change. Recent data is cached for only 5 minutes because today's numbers might still move. Filtered queries (date ranges, specific docs) skip the cache entirely because they're too unique to repeat. The Razor page pre-loads stock data in OnInitializedAsync so by the time the user clicks the Stock tab, the result is already waiting.

3How it works

CachedStockService.GetArticleStockByDateAsync builds a cache key like stock_{artigoId}_{date:yyyyMMdd}, checks _cache.TryGetValue first, falls through to _innerService.GetArticleStockByDateAsync if missed, then writes back with TimeSpan.FromHours(1) or TimeSpan.FromMinutes(5) depending on the date. The underlying SQL is a SUM over entradas/saidas with a +1 day trick to include all movements on the boundary date. ArtigoDetalhe.razor stores _stockSummaryTask = StockService.GetCurrentStockAsync(artigo.Id) in OnInitializedAsync, then the OnStockTabClick handler just awaits that already-running task. DI is wired so IStockService resolves to CachedStockService wrapping a concrete StockService.

💡 O Génio do Caching Explicado

O Que é Caching?

Analogia do mundo real: É como ter post-its na sua secretária!

Sem caching: Sempre que alguém pergunta "Qual é o número do João?", você abre a lista telefónica, procura o João, e diz-lhes

Com caching: A primeira vez que alguém pergunta, escreve num post-it. Da próxima vez? Só lê o post-it!

Como Funciona o Seu Cache Inteligente

public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId, DateTime date)
{
// Cria um "nome" único para esta pergunta
var cacheKey = $"stock_{artigoId}_{date:yyyyMMdd}";
// Verifica os nossos "post-its" primeiro
if (_cache.TryGetValue<ArtigoStock>(cacheKey, out var cachedStock))
{
// Encontrou! Devolve a resposta guardada (SUPER RÁPIDO!)
return cachedStock;
}
// Não está em cache, precisa calcular
var stock = await _innerService.GetArticleStockByDateAsync(artigoId, date);
// Guarda para a próxima vez com expiração inteligente
if (date < DateTime.Today.AddDays(-7))
_cache.Set(cacheKey, stock, TimeSpan.FromHours(1)); // Dados antigos = cache mais longo
else
_cache.Set(cacheKey, stock, TimeSpan.FromMinutes(5)); // Dados recentes = cache mais curto
return stock;}

A Estratégia Brilhante de Cache Baseada em Tempo

O seu sistema é inteligente sobre QUANDO esquecer dados em cache:

Dados Históricos (>7 dias atrás) 📅

Cache por 1 HORA

Porquê? Stock antigo não muda!

Como guardar a lista telefónica do ano passado - não vai mudar

Dados Recentes (<7 dias atrás) 📆

Cache por 5 MINUTOS

Porquê? Stock recente ainda pode estar a mudar

Como o horário de entregas de hoje - pode ter atualizações

Queries Filtradas 🔍

NÃO guardadas em cache

Porquê? Muito específicas, improvável serem perguntadas novamente

Como perguntar "Mostra-me só entregas de terça de itens azuis"

🔧 Funções Principais Explicadas

1. GetArticleStockByDateAsync - "Máquina do Tempo para Stock"

O que faz: Diz-lhe exatamente que stock tinha em qualquer data

Analogia do mundo real: Como perguntar "Quanto tinha na minha conta bancária a 15 de janeiro?"

Como funciona:

-- Por trás dos bastidores, executa algo como:
SELECT
SUM(entradas) as ENTRADA,       -- Tudo que ENTROU
SUM(saidas) as SAIDA,          -- Tudo que SAIU
SUM(entradas - saidas) as STOCK  -- O que SOBROU
FROM movimentos
WHERE data <= '2024-01-15'

Truque inteligente: Adiciona 1 dia para incluir todas as transações do dia!

2. GetStockMovementsAsync - "O Livro de História"

O que faz: Mostra cada movimento (entrada/saída) de um item

Analogia do mundo real: Como o seu extrato bancário mostrando cada transação

Devolve: Uma lista como:

✅ 10 Jan: +100 unidades (Ordem de Compra #1234)

❌ 11 Jan: -20 unidades (Ordem de Venda #5678)

✅ 12 Jan: +50 unidades (Produção #910)

3. GetStockTotalsAsync - "O Resumo"

O que faz: Só dá os totais (quanto entrou, quanto saiu)

Analogia do mundo real: Como perguntar "Quanto ganhei vs gastei este mês?"

Cache inteligente: Só guarda totais "desde sempre", nunca os filtrados por data

4. CheckFluxoAsync - "O Inspetor Especial"

O que faz: Verifica o fluxo de stock para linhas de documento específicas

Analogia do mundo real: Como rastrear um pacote específico no seu envio

Nota: Nunca em cache porque é muito específico!

O sistema sabe quando esquecer dados em cache:

Dados recentes expiram rapidamente (5 minutos)

Queries filtradas não são guardadas em cache

🛠️ Configuração e Setup

Registo Básico do Serviço

// Em Program.cs
services.AddScoped<IStockService, StockService>();
services.AddMemoryCache(); // Ativar caching

Com Wrapper de Caching

// Registar ambos os serviços
services.AddScoped<StockService>();
services.AddScoped<IStockService>(provider =>
{
var innerService = provider.GetRequiredService<StockService>();
var cache = provider.GetRequiredService<IMemoryCache>();
var logger = provider.GetRequiredService<ILogger<CachedStockService>>();
return new CachedStockService(innerService, cache, logger);
});

🎯 Porque Este Design é Brilhante

1. Separação de Responsabilidades

StockService: Faz o trabalho real

CachedStockService: Gere memória/caching

UI (Razor): Apenas exibe dados

2. Padrão Decorator

O serviço com cache "decora" o serviço real:

Pedido → ServiçoCache → (se necessário) → ServiçoStock → BaseDados
↓ (se em cache)
Devolve imediatamente

3. Pré-carregamento Inteligente

Começa a carregar antes do utilizador precisar = resposta percebida como instantânea!

4. Expiração Graduada de Cache

Dados antigos = estáveis = cache mais longo

Dados novos = mutáveis = cache mais curto

Dados filtrados = únicos = não guardar em cache

🐛 Problemas Comuns e Soluções

"Stock parece desatualizado"

Solução: Clique no botão atualizar ou espere 5 minutos para o cache expirar

"Queries filtradas são lentas"

Esperado: Queries filtradas não são guardadas em cache por design (muito específicas)

"Uso de memória está alto"

Verificar: Cache pode estar a guardar demais. Reduza tempos de cache ou adicione limites de memória

Key takeaways

  • The decorator pattern lets you add caching as a transparent wrapper without modifying the original service
  • Cache expiration should match data volatility: longer for historical data, shorter for recent, none for filtered queries
  • Task pre-loading in OnInitializedAsync makes tab clicks feel instant because the work happens during render time
  • Cache keys should encode every parameter that affects the answer (article ID + date in this case)
  • DI registration for decorated services uses a factory delegate that resolves the inner service then wraps it
  • GetStockTotalsAsync only caches the unfiltered totals - filtered queries skip cache because they're too unique to repeat
