Imagine a warehouse worker asking 'how many of this part did we have last Tuesday?' and the system taking three seconds to answer. Now imagine three workers asking it simultaneously. Now imagine a hundred. This document is how that question went from 3000ms to 1ms.

Executive summary

This is the formal Portuguese-language technical document for the production stock service in the BioBraga project. It defines the IStockService interface, the StockService base implementation, and the CachedStockService decorator that wraps it with IMemoryCache. The system uses SQL Server table-valued functions (fn_ArtigoStockByDate, fn_ArtigoUsedInFluxo) for heavy aggregation, IDbContextFactory for connection pooling, and a graduated cache expiration strategy (1 hour for historical data >7 days, 5 minutes for recent data). The Razor UI (ArtigoDetalhe.razor) preloads stock as fire-and-forget tasks during OnInitializedAsync so the user perceives instant response when clicking the stock tab.

💡
MetaphorThe stock service is like a librarian with a photographic memory and a stack of bookmarks: when you ask for a book she's already fetched recently, she hands it to you instantly from her desk; for older books she has the catalog number memorized but still has to walk to the shelves. And while you're still browsing the introduction, she's already gone to fetch the books she predicts you'll ask for next — that's the preload pattern.

1Why it exists

The BioBraga inventory module needs to answer 'how many of this article are in stock right now (or on this past date)?' instantly, even though the underlying calculation is a complex aggregation across CrmDocumentoDetalhes, CrmDocumentos, and CrmTipoDocumentos tables that costs ~2 seconds when run cold. Without intelligent caching the article-detail page would be unusable. The system also needs to distinguish historical data (immutable, can be cached for an hour) from today's data (still moving, cache only 5 minutes).

2What it does

Provides real-time and historical stock queries via IStockService with four core operations: GetArticleStockByDateAsync (point-in-time stock balance), GetStockMovementsAsync (filtered movement history), GetStockTotalsAsync (aggregated entradas/saidas), and CheckFluxoAsync (per-line document flow check). A CachedStockService decorator wraps the base implementation with IMemoryCache, generating cache keys like 'stock_{artigoId}_{yyyyMMdd}' and applying graduated expiration. Performance metrics reported: cached queries run in 1-2ms versus 1500-3000ms cold.

3How it works

StockService calls the SQL function fn_ArtigoStockByDate directly via raw ADO.NET (DbCommand + SqlParameter) because EF Core's overhead is unnecessary for a single-row lookup; it adds a day to the input date to get end-of-day inclusion. GetStockMovementsAsync uses LINQ joins across four tables filtered by Movstocks=true and date range. The CachedStockService checks IMemoryCache, falls through to the inner service on miss, and chooses 1-hour vs 5-minute expiration based on whether the date is older than 7 days. The Razor page initializes a Task<ArtigoStock> field as fire-and-forget during OnInitializedAsync so when the user clicks the stock tab, the awaited task is usually already complete. DI registration uses a manual factory to wire the decorator around the inner service.

Objetivo

O Sistema de Serviço de Stock fornece rastreamento de inventário em tempo real de alta performance com mecanismos inteligentes de cache para minimizar a carga da base de dados mantendo a precisão dos dados.

Implementação StockService

GetArticleStockByDateAsync

public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId, DateTime date)
{
// Crítico: Adicionar um dia para inclusão de fim de dia
var dateWithTime = date.Date.AddDays(1);
await using var dbContext = await _contextFactory.CreateDbContextAsync();
await using var connection = dbContext.Database.GetDbConnection();
await connection.OpenAsync();
// Chamada direta de função SQL para performance
await using var command = connection.CreateCommand();
command.CommandText = "SELECT * FROM dbo.fn_ArtigoStockByDate(@ArtigoId, @Date)";
command.CommandType = CommandType.Text;
// Parâmetros fortemente tipados previnem SQL injection
command.Parameters.Add(new SqlParameter("@ArtigoId", SqlDbType.Int) { Value = artigoId });
command.Parameters.Add(new SqlParameter("@Date", SqlDbType.DateTime) { Value = dateWithTime });
await using var reader = await command.ExecuteReaderAsync();
if (await reader.ReadAsync())
{
return new ArtigoStock
{
ArtigoId = reader.GetInt32(reader.GetOrdinal("ARTIGO_ID")),
Entrada = reader.GetDecimal(reader.GetOrdinal("ENTRADA")),
Saida = reader.GetDecimal(reader.GetOrdinal("SAIDA")),
Stock = reader.GetDecimal(reader.GetOrdinal("STOCK"))
};
}
return null;
}

GetStockMovementsAsync

public async Task<List<StockMov>> GetStockMovementsAsync(
int artigoId,
DateTime? startDate = null,
DateTime? endDate = null)
{
using var dbContext = await _contextFactory.CreateDbContextAsync();
// Join LINQ complexo para rastreamento de movimentos
var query = dbContext.CrmDocumentoDetalhes
.Join(dbContext.CrmDocumentos,
detalhe => detalhe.Documentoid,
doc => doc.Id,
(detalhe, doc) => new { detalhe, doc })
.Join(dbContext.CrmTipoDocumentos,
x => x.doc.Tipodocumentoid,
tipo => tipo.Id,
(x, tipo) => new { x.detalhe, x.doc, tipo })
.Join(dbContext.CrmSerieDocumentos,
x => x.doc.Serieid,
serie => serie.Id,
(x, serie) => new { x.detalhe, x.doc, x.tipo, serie })
.Where(x => x.detalhe.ArtigoId == artigoId && x.tipo.Movstocks == true);
// Filtragem dinâmica por data
if (startDate.HasValue)
query = query.Where(x => x.doc.Data >= startDate.Value.Date);
if (endDate.HasValue)
query = query.Where(x => x.doc.Data <= endDate.Value.Date.AddDays(1).AddSeconds(-1));
return await query
.Select(x => new StockMov
{
ArtigoId = x.detalhe.ArtigoId,
doc = x.doc,
docdetalhe = x.detalhe,
doctipo = x.tipo,
docserie = x.serie
})
.OrderByDescending(s => s.doc.Data)
.ToListAsync();
}

public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId, DateTime date)
{
var cacheKey = $"stock_{artigoId}_{date:yyyyMMdd}";
// Cache L1: Verificação de Memória
if (_cache.TryGetValue<ArtigoStock>(cacheKey, out var cachedStock))
{
_logger.LogDebug("Stock cache hit para artigo {ArtigoId} na data {Date}",
artigoId, date);
return cachedStock;
}
// L2: Consulta Base de Dados
var stock = await _innerService.GetArticleStockByDateAsync(artigoId, date);
if (stock != null)
{
// Expiração inteligente baseada na idade dos dados
var cacheExpiration = date.Date < DateTime.Today.AddDays(-7)
? TimeSpan.FromHours(1)      // Histórico: 1 hora
: TimeSpan.FromMinutes(5);   // Recente: 5 minutos
_cache.Set(cacheKey, stock, cacheExpiration);
}
return stock;
}

Tipo de Query Duração Cache Justificação
Stock Histórico (>7 dias) 1 hora Dados são imutáveis
Stock Recente (<7 dias) 5 minutos Pode ainda mudar
Stock Atual (hoje) 5 minutos Transações ativas
Movimentos Filtrados Não em cache Muito específico
Totais Desde Sempre 5 minutos Frequentemente acedido
Fluxo de Documento Não em cache Específico da transação

Funções SQL Server

fn_ArtigoStockByDate

-- Assinatura da função (implícita)
CREATE FUNCTION dbo.fn_ArtigoStockByDate
(
@ArtigoId INT,
@Date DATETIME
)
RETURNS TABLE
AS
RETURN
(
SELECT
@ArtigoId as ARTIGO_ID,
ISNULL(SUM(CASE WHEN t.Entradasaida = 'E' THEN d.Quantidade END), 0) as ENTRADA,
ISNULL(SUM(CASE WHEN t.Entradasaida = 'S' THEN d.Quantidade END), 0) as SAIDA,
ISNULL(SUM(CASE WHEN t.Entradasaida = 'E' THEN d.Quantidade
WHEN t.Entradasaida = 'S' THEN -d.Quantidade END), 0) as STOCK
FROM CrmDocumentoDetalhes d
JOIN CrmDocumentos doc ON d.Documentoid = doc.Id
JOIN CrmTipoDocumentos t ON doc.Tipodocumentoid = t.Id
WHERE d.ArtigoId = @ArtigoId
AND doc.Data < @Date
AND t.Movstocks = 1
)

private async Task OnStockTabClick()
{
if (stockTabFirstLoad && artigo != null)
{
isLoadingStock = true;
StateHasChanged();
try
{
// Se pré-carregado, isto completa imediatamente
if (_stockSummaryTask != null)
{
currentStock = await _stockSummaryTask;
}
else
{
// Fallback se não pré-carregado
currentStock = await StockService.GetCurrentStockAsync(artigo.Id);
}
// Atualiza estatísticas
if (currentStock != null)
{
stat_stock_e = currentStock.Entrada;
stat_stock_s = currentStock.Saida;
}
}
finally
{
isLoadingStock = false;
stockTabFirstLoad = false;
StateHasChanged();
}
}
}

Filtragem por Data com Gestão de Tarefas

private async Task ShowStockHistory()
{
showStockHistory = true;
// Padrão de reutilização inteligente de tarefas
if (stocklist == null || !stocklist.Any() || isFiltered)
{
isLoadingHistory = true;
StateHasChanged();
try
{
if (isFiltered)
{
// Cria nova tarefa filtrada
_stockMovementsTask = StockService.GetStockMovementsAsync(
artigo.Id, filterStartDate, filterEndDate);
// Cálculo paralelo de totais
var totalsTask = StockService.GetStockTotalsAsync(
artigo.Id, filterStartDate, filterEndDate);
// Aguarda ambos
stocklist = await _stockMovementsTask;
var (entradas, saidas) = await totalsTask;
stat_stock_e = entradas;
stat_stock_s = saidas;
}
else
{
// Reutiliza ou cria tarefa não filtrada
if (_stockMovementsTask == null)
{
_stockMovementsTask = StockService.GetStockMovementsAsync(artigo.Id);
}
stocklist = await _stockMovementsTask;
}
}
finally
{
isLoadingHistory = false;
StateHasChanged();
}
}
}

Problema Sintomas Solução
Pressão de Memória de Cache Alto uso de memória, respostas lentas Reduzir duração de cache ou implementar limites de tamanho

Não guardar dados mutáveis por longos períodos

Não esquecer de lidar graciosamente com cache misses

Não ignorar avisos de pressão de memória

Key takeaways

  • Wrap real services with decorators rather than putting cache logic inside them — keeps SRP intact
  • Use graduated expiration: immutable historical data can cache for hours, recent data only minutes
  • Skip EF Core for tight single-row lookups; raw DbCommand calling SQL functions is much faster
  • Preload expensive operations as Task<T> fields in OnInitializedAsync — by the time the user clicks the tab, the result is ready
  • Don't cache filtered or per-transaction queries — they're too specific to ever be hit again
  • Always measure: this doc shows 99.9% latency reduction (2000ms -> 1ms) for cached queries
