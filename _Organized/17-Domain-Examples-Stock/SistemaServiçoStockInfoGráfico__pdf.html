"Para Totós"



   O Que É Este Serviço de Stock?



Imagine que gere um armazém e precisa de saber exatamente quantos itens tem a qualquer

momento. Este Serviço de Stock é como ter um assistente de inventário super-inteligente que:



    • Sabe exatamente o que está em stock agora mesmo

    • Lembra-se do que entrou e do que saiu

    • Pode dizer-lhe o que tinha em qualquer data específica

    • Funciona RÁPIDO ao lembrar-se de respostas recentes (caching)



Pense nisto como a lista de contactos do seu telemóvel - em vez de ligar às informações

sempre, o seu telemóvel lembra-se dos números que usa frequentemente!



   A Visão Geral



Que Problemas Resolve?



Sem este sistema:



•  Cada verificação de stock significa contar tudo outra vez (lento!)



•  Não consegue ver níveis históricos de stock



•  A base de dados fica sobrecarregada com as mesmas perguntas



•  Os utilizadores esperam eternamente por relatórios de stock



•  O servidor trabalha demais a responder a perguntas repetidas



Com este sistema:



•  Verificações de stock ultra-rápidas (lembra-se de respostas recentes)



•  Rastreamento histórico de stock ("O que tínhamos na terça passada?")



•  Cache inteligente (não faz a mesma pergunta duas vezes)



•  Rastreamento preciso de movimentos (cada entrada e saída)



•  O servidor mantém-se feliz e responsivo

    O Génio do Caching Explicado



O Que é Caching?



Analogia do mundo real: É como ter post-its na sua secretária!



    • Sem caching: Sempre que alguém pergunta "Qual é o número do João?", você abre a

         lista telefónica, procura o João, e diz-lhes



    • Com caching: A primeira vez que alguém pergunta, escreve num post-it. Da próxima

         vez? Só lê o post-it!



Como Funciona o Seu Cache Inteligente



public async Task<ArtigoStock?> GetArticleStockByDateAsync(int artigoId,

DateTime date)

{



       // Cria um "nome" único para esta pergunta

       var cacheKey = $"stock_{artigoId}_{date:yyyyMMdd}";



       // Verifica os nossos "post-its" primeiro

       if (_cache.TryGetValue<ArtigoStock>(cacheKey, out var cachedStock))

       {



              // Encontrou! Devolve a resposta guardada (SUPER RÁPIDO!)

              return cachedStock;

       }



       // Não está em cache, precisa calcular

       var stock = await _innerService.GetArticleStockByDateAsync(artigoId,

date);



       // Guarda para a próxima vez com expiração inteligente

       if (date < DateTime.Today.AddDays(-7))



              _cache.Set(cacheKey, stock, TimeSpan.FromHours(1)); // Dados

antigos = cache mais longo



       else

              _cache.Set(cacheKey, stock, TimeSpan.FromMinutes(5)); // Dados



recentes = cache mais curto



       return stock;}

A Estratégia Brilhante de Cache Baseada em Tempo



O seu sistema é inteligente sobre QUANDO esquecer dados em cache:



1. Dados Históricos (>7 dias atrás)

         o Cache por 1 HORA

         o Porquê? Stock antigo não muda!

         o Como guardar a lista telefónica do ano passado - não vai mudar



2. Dados Recentes (<7 dias atrás)

         o Cache por 5 MINUTOS

         o Porquê? Stock recente ainda pode estar a mudar

         o Como o horário de entregas de hoje - pode ter atualizações



3. Queries Filtradas

         o NÃO guardadas em cache

         o Porquê? Muito específicas, improvável serem perguntadas novamente

         o Como perguntar "Mostra-me só entregas de terça de itens azuis"



Funções Principais Explicadas



1. GetArticleStockByDateAsync - "Máquina do Tempo para Stock"



O que faz: Diz-lhe exatamente que stock tinha em qualquer data



Analogia do mundo real: Como perguntar "Quanto tinha na minha conta bancária a 15 de

janeiro?"



Como funciona:



-- Por trás dos bastidores, executa algo como:



SELECT



SUM(entradas) as ENTRADA,   -- Tudo que ENTROU



SUM(saidas) as SAIDA,       -- Tudo que SAIU



SUM(entradas - saidas) as STOCK -- O que SOBROU



FROM movimentos



WHERE data <= '2024-01-15'



Truque inteligente: Adiciona 1 dia para incluir todas as transações do dia!



2. GetStockMovementsAsync - "O Livro de História"



O que faz: Mostra cada movimento (entrada/saída) de um item



Analogia do mundo real: Como o seu extrato bancário mostrando cada transação



Devolve: Uma lista como:



10 Jan: +100 unidades (Ordem de Compra #1234)

11 Jan: -20 unidades (Ordem de Venda #5678)

12 Jan: +50 unidades (Produção #910)

3. GetStockTotalsAsync - "O Resumo"



O que faz: Só dá os totais (quanto entrou, quanto saiu)

Analogia do mundo real: Como perguntar "Quanto ganhei vs gastei este mês?"

Cache inteligente: Só guarda totais "desde sempre", nunca os filtrados por data



4. CheckFluxoAsync - "O Inspetor Especial"



O que faz: Verifica o fluxo de stock para linhas de documento específicas

Analogia do mundo real: Como rastrear um pacote específico no seu envio

Nota: Nunca em cache porque é muito específico!

3. Invalidação Inteligente de Cache



O sistema sabe quando esquecer dados em cache:



    • Dados recentes expiram rapidamente (5 minutos)

    • Dados antigos expiram lentamente (1 hora)

    • Queries filtradas não são guardadas em cache

Cenário 1: Verificação Diária de Stock



Rotina matinal:

    4. Carrega da base de dados (2 segundos)

    5. Mostra: "Stock: 1.250 unidades"

    6. Guarda em cache por 5 minutos

Cenário 3: Múltiplos Utilizadores



A beleza do caching com múltiplos utilizadores:



    • Utilizador A verifica stock do Artigo #123 (demora 2 segundos, guarda resultado em

         cache)



    • Utilizador B verifica mesmo artigo 30 segundos depois (instantâneo! usa cache)

    • Utilizador C verifica mesmo artigo 1 minuto depois (instantâneo! usa cache)

    • Após 5 minutos, cache expira

    • Próximo utilizador desencadeia novo carregamento

       var cache = provider.GetRequiredService<IMemoryCache>();

provider.GetRequiredService<ILogger<CachedStockService>>();

       return new CachedStockService(innerService, cache, logger);

    Porque Este Design é Brilhante



1. Separação de Responsabilidades



    • StockService: Faz o trabalho real

    • CachedStockService: Gere memória/caching

    • UI (Razor): Apenas exibe dados



2. Padrão Decorator



O serviço com cache "decora" o serviço real:



Pedido → ServiçoCache → (se necessário) → ServiçoStock → BaseDados

                    ↓ (se em cache)



                Devolve imediatamente



3. Pré-carregamento Inteligente



Começa a carregar antes do utilizador precisar = resposta percebida como instantânea!



4. Expiração Graduada de Cache



    • Dados antigos = estáveis = cache mais longo

    • Dados novos = mutáveis = cache mais curto

    • Dados filtrados = únicos = não guardar em cache



    Problemas Comuns e Soluções



"Stock parece desatualizado"



Solução: Clique no botão atualizar ou espere 5 minutos para o cache expirar



"Queries filtradas são lentas"



Esperado: Queries filtradas não são guardadas em cache por design (muito específicas)



"Uso de memória está alto"



Verificar: Cache pode estar a guardar demais. Reduza tempos de cache ou adicione limites

de memória
